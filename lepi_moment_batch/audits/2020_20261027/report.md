# 2020-05-30のfailed表示に関する調査（2026-10-27）

5月30日の全288状態ファイルはcomplete=219、partial=3、excluded=66、failed=0。
excludedは全66件empty_lepi_data。MGF24時間とLEP-i日次の入力25単位はすべてverifiedで、
取得時attemptsにも失敗履歴はなかった。当日のworkerログにもTraceback等の例外は検出されなかった。

確認時点の2020年1～5月の月別集計では、failedがあるのは2月のcalculation_error 5件だけ。
全5件の状態とログを読み、SpacePy _read_config -> _write_defaults -> nextsec未定義のUnboundLocalErrorであることを確認。

対象（2020-02-12、UTC）：

- 06:15–06:20
- 06:20–06:25
- 06:25–06:30
- 06:50–06:55
- 06:55–07:00

5件とも入力検証verifiedで、moment計算前のライブラリimport中に失敗し、NPZは生成されていない。
前回の2021-12-27失敗と同じ直接原因。SpacePy設定の並列更新競合が有力だが、障害時の設定内容は残っておらず、競合自体は推定。
実行中の年次ジョブは--compute-workers 16。compute.pyは共通の環境変数を各子へ継承し、ワーカー専用SPACEPY領域の設定は未実装。

進捗バーは日単位ではなく実行全体の累積countsを表示するため、5月30日の処理中に以前の失敗件数を見ていた可能性が高い。
5月30日と明記された別のエラー行があった場合は、この保存状態との対応は未確認。

現年次ジョブへの停止・変更、データ再取得、moment再計算、コード修正は行っていない。
確認済み5件の状態・ログをこのディレクトリへ保存した。恒久対策はSpacePy設定をワーカーごとに分離すること。
再計算するなら現ジョブ終了後、専用SPACEPY領域を使い1workerで対象5区間を処理する方法が妥当。
