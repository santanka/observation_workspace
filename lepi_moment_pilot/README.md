# LEP-iモーメントの短区間計算・保存の検証

2026-10-07に実データで実行した、KAW解析から独立した試作。
既存のKAWノートブック、バッチ、入力CDFを変更せず、ローカルCDFだけを使用した。
長期間・一日分のモーメント計算は開始していない。

## 検証結果

入力はLEP-i `erg_lepi_l2_3dflux_20220929_v03_00.cdf` と、同日の05時のMGF 64 Hz DSI `v04.06`。
計算対象は2022-09-29 05:05:00–05:20:00 UTCに含まれるスピン。
エネルギー指定は暫定的に30–30000 eV/q、H⁺・He⁺・O⁺を別々に計算した。
PIとの議論前の計算経路・資源・保存検証であり、観測モーメントの物理的精度を検証したものではない。

| 区間長 | 各種のスピン数 | 全体所要時間 | 最大RSS | 保存サイズ |
|---|---:|---:|---:|---:|
| 1分 | 7 | 3.95秒 | 445.9 MiB | 102338 bytes |
| 5分 | 37 | 4.30秒 | 445.8 MiB | 394404 bytes |
| 15分 | 112 | 5.90秒 | 448.1 MiB | 1118525 bytes |

この表は展開済みCDFを再利用した結果。全体所要時間にはPythonのimport、CDF読み込み、
3種のモーメント計算、圧縮保存、保存後の全配列照合を含む。
モーメント計算のみの3種合計は、それぞれ0.24、0.59、1.49秒だった。
環境負荷、OSのファイルキャッシュ、データ状態で時間は変わる。

初回展開をやり直した測定では、LEP-iとMGFの展開に15.48秒、1分区間の全処理に20.22秒、
最大RSSに445.7 MiBを要した。これは展開キャッシュがない場合の測定であり、
OSのファイルキャッシュを消した測定ではない。

検証項目は `results/verification.json`、各試算の時間・メモリは `results/*.metrics.json` に保存した。

- 1分区間について、標準 `cdf_to_tplot` と公開 `lepi()` と同じ整形に対し、時刻・flux・energyが完全一致。
- 標準読み込み確認を経た結果と直接読み込み結果で、全保存配列がNaNの位置を含め完全一致。
- 5分×3区間と15分一括で、48モーメント系列と補助系列を含む63系列が完全一致。
- 分割した時刻は15分一括の112レコードと完全一致し、境界の重複・欠落なし。
- 圧縮保存した全配列を再読み込みし、保存前の配列との完全一致を確認。
- 同一条件の再実行は、設定・配列チェックサムを検証してスキップし、保存ファイルを変更しない。
- 時刻条件を変えて同じ保存先へ実行すると拒否し、既存ファイルを変更しない。
- 初回展開を再実行したCDFのSHA256は、先に作成した展開CDFと一致。

## メモリ増大の原因と回避方法

LEP-i元CDFは88603514 bytesだが、ファイル全体がgzip圧縮されており、
展開後は1322869516 bytes（約1.23 GiB）になる。
通常の `cdflib.CDF()` は `gzip.decompress` で全体をメモリ上に展開する。
3 GiBの仮想メモリ上限では、この処理がMemoryErrorで停止した。
時間範囲を短くするだけでは、CDFを開くときのピークを抑えられない。

試作では1 MiB以下の出力バッファでストリーム展開し、`/tmp/lepi_moment_pilot_cdf/` に保存する。
gzipのCRC・終端とCDFヘッダの展開サイズを確認し、展開データのSHA256も記録する。
展開後は `varget(startrec=..., endrec=...)` で必要なレコードだけを読む。
日全体のEpochと、MGF一時間分のEpochは時刻検索のために読むが、日全体のfluxは通常処理では読まない。
標準読み込みの比較試験だけは、各種の一日分のfluxを順番に読み込んだ。

重要な整形条件は、最初の30エネルギーチャンネル、anode番号0–7、sector番号0–15。
CDFのsector値をそのまま使わず、公開 `lepi()` と同様に0–15へ置換する。
浮動小数点のFILLVALは標準importerと同じくNaNにする。
公開getterは第0エネルギーチャンネルを無効化し、有限な負fluxをゼロにする。
これらは変更していない。元の負fluxビン数も補助量として保存する。

## 保存内容

NPZに各種の公開出力16種類を保存する。

`density`, `flux`, `mftens`, `velocity`, `ptens`, `ttens`, `vthermal`, `avgtemp`,
`eflux`, `t3`, `magt3`, `symm`, `symm_phi`, `symm_theta`, `symm_ang`, `qflux`

追加で、TT2000時刻、Unix時刻、sector時刻、種別energy表・選択チャンネル、
raw counts、未解釈のraw quality、選択範囲内の有限flux率、負fluxビン数、
MGFの時刻・磁場・raw quality、実際に積分器へ供給した補間磁場を保持する。
qualityは生の整数値を保持し、LEP-i quality配列の15 anodeも削らず残す。

`manifest_json` に設定、入力パス・版・サイズ・更新時刻、使用したflux配列のSHA256、
主要計算ソースと試作コードのSHA256、パッケージ版、公開出力メタデータ、
単位の補足、テンソル成分順序、補正・選別状況を保存する。
保存した全数値配列にもSHA256を付ける。

速度・テンソルは公開計算のDSI出力を保持する。速度の衛星運動補正は行わず、
宇宙機電位は公開実装どおり0 V、FAC・GSM変換も行っていない。
`magt3` の内部磁場基底は地理的に固定したFACではない。
6成分テンソルの順序は `xx, yy, zz, xy, xz, yz`。
密度はcm⁻³、速度・熱速度はkm/s、温度テンソルはeV、圧力テンソルはeV/cm³。

NPZは `allow_pickle=False` で読み込める。

```python
import json
import numpy as np

with np.load('lepi_moment_pilot/results/direct_300s.npz', allow_pickle=False) as data:
    time_tt2000 = data['epoch_tt2000']
    velocity_h = data['FPDU__velocity']
    pressure_h = data['FPDU__ptens']
    temperature_h = data['FPDU__ttens']
    metadata = json.loads(str(data['manifest_json']))
```

## 実行方法と負荷制限

ワークスペースのルートから、専用仮想環境で実行する。

```bash
ionice -c 3 timeout 180s .venv_pyspedas/bin/python lepi_moment_pilot/pilot.py \
  --start 2022-09-29T05:05:00 --seconds 300 \
  --output lepi_moment_pilot/results/direct_300s.npz
```

試作は内部でnice=19、CPU affinityを許可CPUの最後の1個、BLAS等を1スレッドに設定する。
仮想メモリを3 GiB、CPU時間を120秒（hard limit 125秒）に制限する。
上記コマンドはさらにidle I/O priorityと180秒のwall timeoutを設定する。
同時ワーカーは1本とする。既存プロセスの優先度・affinityは変更しない。

試算前にはKAWの2020年1月・2月バッチ2本とその子カーネルが動作していた。
16論理CPU、使用可能メモリ約34 GiBを確認した。
途中の再確認でも2本のバッチは継続し、使用可能メモリは約27 GiBだった。
既存負荷が時間とともに変動するため、KAWへの速度影響がゼロとは判定できない。
低優先度・1 CPUはCPU競合を抑えるが、ディスクI/Oとキャッシュ競合を完全には消さない。

## 本処理へ移す際の暫定仕様

日ごとに一度CDFを展開し、5分区間を1プロセスずつ順番に処理する構成が有力。
区間は `[start, end)` で選択し、スピンのレコードを丸ごと保持する。
各プロセス終了でtplot状態とメモリを確実に解放する。
暫定保存先はKAWの出力から独立したディレクトリを設ける。
NPZは試作には適するが、長期統計向けのNetCDF/Parquet等は別途決める。

本試作は単一LEP-i CDF・単一MGF 64 Hz CDF、固定energy表、32×8×16幾何、
非ゼロかつ有限なMGFが区間を挟む場合のみを扱う。
日・時の境界、磁場欠測、異なるモード、欠けた種、無データ区間、その他のCDF圧縮は未対応。
qualityの意味・適切な選別、電位補正、sub anodeの採用はPIとの議論事項。
試作は物理精度を保証するものではなく、他の日の資源使用量も未測定。

本処理では、残メモリによる開始待機、区間間の休止、失敗状態・タイムアウト記録、
一時ファイルの掃除、展開キャッシュの排他制御と日終了後の削除を追加する必要がある。
試作の再開チェックはNPZ自身で行い、資源測定JSONは補助記録である。
強制終了時に残った `.npz.tmp` は自動再開の対象にしていない。

展開キャッシュは合計約1.25 GiBを `/tmp/lepi_moment_pilot_cdf/` に保持している。
一日ごとに削除・再作成する本処理なら、日数に比例して蓄積させる必要はない。
